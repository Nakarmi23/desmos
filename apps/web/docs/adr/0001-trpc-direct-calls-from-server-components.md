# tRPC procedures called directly (not over HTTP) from Server Components

Server Components render the initial page load by calling tRPC procedures directly via `appRouter.createCaller()` — no HTTP hop — with `@trpc/tanstack-react-query`'s hydration helpers seeding the client-side React Query cache from that result. Once the page is interactive, further client-driven data needs (e.g. dynamic or scroll-based pagination) go over HTTP via `httpBatchLink` from Client Components through `app/api/trpc/[trpc]/route.ts`, not through the server-side caller. We chose this over routing every call (including the initial server-side one) through HTTP because a self-hosted app hitting its own endpoint from the same process is a pointless network hop for first paint, while everything client-triggered already needs the HTTP path anyway.

**Consequences**: this couples the initial-load code path in Server Components to the tRPC router living in-process with the Next.js server. If the API is ever split into a standalone service, only those direct `createCaller` call sites need to become HTTP calls — client-side pagination/interaction code already goes over HTTP and needs no change.
